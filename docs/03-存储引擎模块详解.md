# TiKV 存储引擎模块详解

## 1. 模块概述

TiKV 的存储引擎模块采用了分层设计，通过抽象层支持多种存储后端。当前主要使用 RocksDB 作为底层存储引擎，同时提供了良好的扩展性，支持其他存储引擎的接入。

### 1.1 设计目标

- **高性能**: 提供高吞吐量、低延迟的存储服务
- **可扩展性**: 支持多种存储引擎后端
- **一致性**: 确保数据的一致性和持久性
- **可靠性**: 支持数据恢复和故障处理

### 1.2 模块组成

```
存储引擎模块
├── engine_traits/     # 存储引擎抽象层
├── engine_rocks/      # RocksDB 实现
├── engine_tirocks/    # TiRocks 优化版本
├── in_memory_engine/  # 内存引擎实现
└── hybrid_engine/     # 混合引擎实现
```

### 3.4 核心操作实现

#### 3.4.1 读取操作

```rust
impl Engine for RocksEngine {
    fn get(&self, key: &[u8]) -> Result<Option<Vec<u8>>> {
        // 1. 获取适当的列族句柄
        let cf_handle = self.get_cf_handle_by_key(key)?;

        // 2. 执行读取
        let result = self.db.get_cf(cf_handle, key)?;

        // 3. 更新统计信息
        if let Some(stats) = &self.statistics {
            stats.inc_read_count();
            stats.add_read_bytes(key.len() + result.as_ref().map_or(0, |v| v.len()));
        }

        Ok(result)
    }

    fn get_value(&self, key: &Key) -> Result<Option<Value>> {
        let raw_key = key.to_raw()?;
        let raw_value = self.get(&raw_key)?;
        raw_value.map(|v| Value::from_vec(v)).transpose()
    }
}
```

#### 3.4.2 写入操作

```rust
impl Engine for RocksEngine {
    fn write(&self, batch: WriteBatch) -> Result<()> {
        // 1. 创建 RocksDB 写入批处理
        let rocks_batch = WriteBatch::default();

        // 2. 转换批处理操作
        for op in batch.into_iter() {
            match op {
                WriteOp::Put { cf, key, value } => {
                    let cf_handle = self.get_cf_handle(cf)?;
                    rocks_batch.put_cf(cf_handle, &key, &value)?;
                }
                WriteOp::Delete { cf, key } => {
                    let cf_handle = self.get_cf_handle(cf)?;
                    rocks_batch.delete_cf(cf_handle, &key)?;
                }
                WriteOp::DeleteRange { cf, begin_key, end_key } => {
                    let cf_handle = self.get_cf_handle(cf)?;
                    rocks_batch.delete_range_cf(cf_handle, &begin_key, &end_key)?;
                }
            }
        }

        // 3. 执行写入
        let start_time = Instant::now();
        self.db.write(rocks_batch)?;

        // 4. 更新统计信息
        if let Some(stats) = &self.statistics {
            stats.inc_write_count();
            stats.add_write_duration(start_time.elapsed());
        }

        Ok(())
    }
}
```

```rust
impl Engine for HybridEngine {
    fn get(&self, key: &[u8]) -> Result<Option<Vec<u8>>> {
        // 1. 首先检查内存引擎
        if let Some(value) = self.memory_engine.get(key)? {
            return Ok(Some(value));
        }

        // 2. 检查是否需要从持久化引擎加载
        if self.should_load_from_persistent(key)? {
            let value = self.persistent_engine.get(key)?;

            // 3. 将数据提升到内存引擎
            if let Some(value) = &value {
                self.memory_engine.put(key, value)?;
                self.update_access_statistics(key)?;
            }

            return Ok(value);
        }

        Ok(None)
    }

    fn write(&self, batch: WriteBatch) -> Result<()> {
        // 1. 写入内存引擎
        self.memory_engine.write(batch.clone())?;

        // 2. 异步写入持久化引擎
        let persistent_engine = self.persistent_engine.clone();
        tokio::spawn(async move {
            if let Err(e) = persistent_engine.write(batch) {
                error!("Failed to write to persistent engine: {}", e);
            }
        });

        Ok(())
    }
}
```

### 6.2 并发控制

```rust
impl InMemoryEngine {
    pub fn get(&self, key: &[u8]) -> Result<Option<Vec<u8>>> {
        // 1. 获取读锁
        let _read_guard = self.read_locks.read().unwrap();

        // 2. 根据 key 类型选择适当的 map
        let map = self.get_map_by_key(key)?;

        // 3. 执行读取
        let result = map.get(key).map(|v| v.to_vec());

        // 4. 更新统计信息
        self.statistics.inc_read_count();

        Ok(result)
    }

    pub fn put(&self, key: &[u8], value: &[u8]) -> Result<()> {
        // 1. 获取写锁
        let mut write_guard = self.write_locks.lock().unwrap();

        // 2. 检查是否有冲突的读操作
        if self.has_conflicting_reads(key) {
            return Err(Error::WriteConflict);
        }

        // 3. 根据 key 类型选择适当的 map
        let map = self.get_map_by_key(key)?;

        // 4. 执行写入
        map.insert(key.to_vec(), value.to_vec());

        // 5. 更新统计信息
        self.statistics.inc_write_count();
        self.statistics.add_data_size(key.len() + value.len());

        Ok(())
    }
}
```

```rust
impl ReadOptimizations {
    pub fn prefetch_next_block(&self, iterator: &mut Iterator) {
        // 预取下一个数据块
        if let Some(next_key) = iterator.peek_next_key() {
            self.block_cache.prefetch(&next_key);

    pub async fn parallel_read(&self, keys: Vec<&[u8]>) -> Vec<Result<Option<Vec<u8>>>> {
        // 并行读取多个键
        let tasks = keys.into_iter().map(|key| {
            let engine = self.engine.clone();
            let key = key.to_vec();
            async move {
                tokio::task::spawn_blocking(move || {
                    engine.get(&key)
                }).await.unwrap_or(Err(Error::TaskFailed))
            }
        });

        futures::future::join_all(tasks).await
    }
}
```

### 7.2 写入优化

```rust
impl WriteOptimizations {
    pub fn batch_write_optimization(&self, batch: &mut WriteBatch) {
        // 1. 按列族分组
        let mut by_cf = HashMap::new();
        for op in batch.iter() {
            by_cf.entry(op.cf()).or_insert_with(Vec::new).push(op);
        }

        // 2. 按键排序以优化写入模式
        for (_, ops) in by_cf.iter_mut() {
            ops.sort_by_key(|op| op.key());
        }

        // 3. 合并连续的删除范围操作
        self.merge_delete_ranges(batch);
    }

    pub fn async_write(&self, batch: WriteBatch) -> impl Future<Output = Result<()>> {
        let engine = self.engine.clone();
        async move {
            // 使用线程池异步执行写入
            tokio::task::spawn_blocking(move || {
                engine.write(batch)
            }).await.unwrap_or(Err(Error::TaskFailed))
        }
    }
}
```

### 7.3 缓存策略

```rust
impl CacheStrategy {
    pub fn lru_eviction(&self, cache: &mut LRUCache) {
        // LRU 淘汰策略
        while cache.size() > self.max_size {
            if let Some((key, _)) = cache.pop_least_recently_used() {
                self.evict_from_memory(&key);
            }
        }
    }

    pub fn ttl_eviction(&self, cache: &mut TTLCache) {
        // TTL 淘汰策略
        let now = SystemTime::now();
        cache.retain(|_, (_, ttl)| {
            now.duration_since(*ttl).unwrap_or_default() < self.max_ttl
        });
    }

    pub fn adaptive_cache(&self, access_pattern: &AccessPattern) -> CachePolicy {
        // 自适应缓存策略
        match access_pattern {
            AccessPattern::Sequential => CachePolicy::Prefetch,
            AccessPattern::Random => CachePolicy::LRU,
            AccessPattern::Temporal => CachePolicy::TTL,
        }
    }
}
```

```rust
        // 1. 检查数据完整性
        self.check_data_integrity(engine_path).await?;

        // 2. 重建缓存

    pub async fn check_data_integrity(&self, path: &str) -> Result<()> {

        let options = Options::default();
        let db = DB::open_for_read_only(&options, path, false)?;

        // 检查所有列族的完整性
        for cf_name in CfName::all() {
            let cf_handle = db.cf_handle(cf_name.name())
                .ok_or_else(|| Error::InvalidFormat("Column family not found".to_string()))?;

            // 运行完整性检查

            iterator.collect::<Vec<_>>();
        }

    }
```

```rust
    pub write_errors: AtomicU64,
```

### 10.2 指标收集

```rust
impl MetricsCollector {
    pub fn collect_engine_metrics(&self, engine: &RocksEngine) -> EngineMetrics {
        let metrics = EngineMetrics::new();

        // 收集 RocksDB 统计信息
        if let Some(stats) = &engine.statistics {
            metrics.set_read_count(stats.get_read_count());
            metrics.set_write_count(stats.get_write_count());
            metrics.set_block_cache_usage(stats.get_block_cache_usage());
        }

        // 收集性能指标
        metrics.update_latency_metrics();

        // 收集错误指标
        metrics.update_error_metrics();

        metrics
    }
}
```

## 11. 总结

TiKV 的存储引擎模块通过分层抽象设计，实现了高性能、高可靠的存储服务。关键特点包括：

1. **抽象层设计**: 通过 trait 抽象支持多种存储引擎
2. **RocksDB 优化**: 针对分布式场景深度优化的 RocksDB 实现
3. **多层缓存**: Block Cache、Row Cache、Table Cache 等多层缓存策略
4. **并发控制**: 高效的读写并发控制机制
5. **性能监控**: 全面的性能监控和指标收集
6. **故障恢复**: 完善的错误处理和恢复机制

这些设计使得 TiKV 的存储引擎能够在分布式环境中提供稳定、高效的存储服务，为上层的事务处理和一致性保证奠定坚实基础。
